# Provenance, SBOM, and signing

Container evidence is generated by the existing exact-head container workflow. It includes a deterministic CycloneDX inventory and binds the evidence to the source revision and image identity. The Dockerfile uses a direct digest-pinned Python base and the runtime image is assembled from the locked wheel boundary.

Release provenance and artifact attestations are a platform operation, not a claim made by local tests. A release workflow may use GitHub OIDC artifact attestations when repository settings grant `attestations: write` and `id-token: write`. Signing is permitted only with keyless identity backed by the platform; private keys must never be stored in the repository, image, or application. Verification must check the exact digest, source commit, workflow identity, repository, and ref before promotion.

Images and hosted bundles are promoted by immutable digest or checksum, never by a mutable tag alone. Until a release workflow has produced and independently verified evidence, documentation must say that provenance/signing is configured but not verified for that release.
