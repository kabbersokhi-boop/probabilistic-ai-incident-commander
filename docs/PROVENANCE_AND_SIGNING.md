# Provenance, SBOM, and signing

Container evidence is generated by the existing exact-head container workflow. It includes a deterministic CycloneDX inventory and binds the evidence to the source revision and image identity. The Dockerfile uses a direct digest-pinned Python base and the runtime image is assembled from the locked wheel boundary.

The `Release integrity evidence` workflow uses GitHub OIDC artifact attestations with
`attestations: write` and `id-token: write`. On `main` commit
`32cf1bf7f0d86463d28cfd5a1794bd7f293863bd`, run `30841777500` generated and independently
verified attestations for `bundle.json`, `manifest.json`, and `SHA256SUMS`. Verification
required the repository, exact source ref, release workflow identity, and SLSA provenance
predicate. Future releases must repeat that verification; a past run is not transferable
to a different commit.

Signing is permitted only with keyless identity backed by the platform; private keys must
never be stored in the repository, image, or application. No public OCI registry image is
currently promoted, so OCI image signing is not claimed or required by this static-host
foundation.

Images and hosted bundles are promoted by immutable digest or checksum, never by a mutable
tag alone. Deployment requires the validated closed-world bundle, its manifest, lock
digest, source commit, and release evidence. An attestation is not a deployment or hosted
URL claim.
